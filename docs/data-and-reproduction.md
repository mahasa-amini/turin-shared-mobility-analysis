# Data and reproduction

## Inputs and local layout

The scooter inputs are Bird annual CSV files, Lime monthly CSV files, and Voi monthly Excel workbooks. External inputs comprise Torino statistical-zone shapefile components and extracted GTT GTFS tables. Expected local families are:

```text
data/raw/bird/                      annual rental CSVs
data/raw/lime/                      monthly rental CSVs
data/raw/voi/                       monthly rental workbooks
data/raw/external/torino_zones/     zone_statistiche_geo shapefile and sidecars
data/raw/external/gtt_gtfs/         GTFS text tables, including feed_info.txt
data/interim/                      typed and flagged operator data
data/cleaned/                      finalized operator/year Parquet files
data/processed/                    harmonized and exercise-specific data
audit/                             generated diagnostics, also used as inputs
outputs/tables/                     generated summaries
outputs/figures/                    generated figures
outputs/report/                     local reports and submission artifacts
```

The root `data/`, `audit/`, and `outputs/` directories are excluded by [.gitignore](../.gitignore). They are not supplied by a source checkout. The owner has authorized data publication, but no distribution location or dataset license has yet been established. No verified acquisition date, original GTFS archive, or checksum manifest is supplied. The GTFS metadata and its temporal mismatch are documented in [Methodology](methodology.md).

## Dependency map from source inspection

This is a map of principal dependencies, **not a tested quickstart or guaranteed execution sequence**. Scripts contain local file expectations and checks that need reconciliation during a future controlled run.

| Stage | Principal entry points and prerequisites |
|---|---|
| Operator preparation | `src/cleaning/clean_bird.py`, `audit_lime.py`, `audit_voi.py` read raw inputs; corresponding `finalize_*.py` scripts read typed/flagged intermediates |
| Harmonization | `src/harmonization/harmonize_operators.py` reads six cleaned operator/year files and writes harmonized data plus audit tables |
| Temporal analysis | `exercise1_cleaning_impact.py`, `exercise1_temporal_coverage.py`, and trend/profile/utilization scripts consume harmonized data, audits, and preceding temporal tables |
| Spatial analysis | `exercise2_zoning_audit.py` prepares zones; `exercise2_assign_zones.py` adds trip zones; `exercise2_build_od.py` and `exercise2_temporal_od.py` precede GIS, maps, and appendices |
| PT analysis | `exercise3_prepare_pt_reference.py` needs GTFS and processed zones; `exercise3_pt_proximity.py` needs the PT reference and harmonized trips; `exercise3_route_overlap.py` precedes temporal adduction and related figures/GIS |
| Parking analysis | `exercise4_parking_interval_audit.py` needs harmonized 2024/2025 data; `exercise4_finalize_parking_events.py` also needs zoned 2024 trips; statistics precede OD relationships/maps |
| Economic analysis | `exercise5_revenue_engine.py` and `exercise5_fleet_exposure_audit.py` consume harmonized data/configuration; `exercise5_cost_profitability_engine.py` requires their outputs; diagnostics, robustness, and figures follow |
| Separate commuting exercise | Root Stage 4 scripts supply manually copied Stage 5 costs; Stage 6 reads `stage5_master_modes.csv`; Stage 7 reads Stage 5/6 tables |

Names beginning `exercise` above are under `src/analysis/`; additional plotting scripts are under `src/visualization/`. The [methodology](methodology.md) links the principal implementations and defines their measures.

## Verification status and blockers

All 69 project Python files passed in-memory `ast.parse` with Python 3.13.13 after the isolated PT-reference comma repair at commit `b39ff7cebed5c6632d1ff7e2293ba4376d42a7cc`. This verifies syntax only. No environment installation, module-import checks, end-to-end analysis, or independent result reconciliation has been performed during this repository upgrade. Existing output/audit files are evidence of a previous run.

Known blockers and limitations:

- [requirements.txt](../requirements.txt) omits directly used GeoPandas, Shapely, and python-docx. Installation and compatibility of its pinned versions remain unverified.
- Personal absolute project paths remain in `src/analysis/exercise2_map_temporal_comparison.py`, `exercise2_map_origin_density.py`, `exercise2_appendixA_heatmap.py`, and `exercise2_appendixB_heatmaps.py`. Root Stages 5–7 use working-directory-relative output paths.
- [GTFS acquisition script](../src/data_loading/download_gtt_gtfs_archive.py) is empty. A historical feed matching the scooter observation period is not established by the local feed.
- Stage 4 → Stage 5 commuting costs are manually copied constants; their agreement has not been independently checked.
- `tests/` contains no tests. Several scripts assert dataset-specific counts, and some create directories or perform work at module scope; importing them is not a safe substitute for static inspection.

A future reproduction check needs an agreed data distribution/provenance record, a complete tested environment, portable paths, and a controlled run that regenerates prerequisite audits and reconciles outputs. None of these is presented here as already complete.
