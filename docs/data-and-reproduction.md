# Data and reproduction

## Inputs and local layout

The scooter inputs are Bird annual CSV files, Lime monthly CSV files, and Voi monthly Excel workbooks. External inputs comprise Torino statistical-zone shapefile components and extracted GTT GTFS tables. Expected local families are:

```text
data/raw/bird/                      annual rental CSVs
data/raw/lime/                      monthly rental CSVs
data/raw/voi/                       monthly rental workbooks
data/raw/external/torino_zones/     zone_statistiche_geo shapefile and sidecars
data/raw/external/gtt_gtfs/         GTFS text tables, including feed_info.txt
data/interim/                      typed and flagged operator data
data/cleaned/                      finalized operator/year Parquet files
data/processed/                    harmonized and exercise-specific data
audit/                             generated diagnostics, also used as inputs
outputs/tables/                     generated summaries
outputs/figures/                    generated figures
outputs/report/                     local reports and submission artifacts
```

The root `data/`, `audit/`, and `outputs/` directories are excluded by [.gitignore](../.gitignore). They are not supplied by a source checkout. The owner has authorized data publication, but no distribution location or dataset license has yet been established. No verified acquisition date, original GTFS archive, or checksum manifest is supplied. The GTFS metadata and its temporal mismatch are documented in [Methodology](methodology.md).

| PT analysis | `exercise3_prepare_pt_reference.py` needs GTFS and processed zones; `exercise3_pt_proximity.py` needs the PT reference and harmonized trips; `exercise3_route_overlap.py` precedes temporal adduction and related figures/GIS |

## Verification status and blockers

The original 69 analysis Python files passed in-memory `ast.parse` with Python 3.13.13 after the PT-reference comma repair at commit `b39ff7cebed5c6632d1ff7e2293ba4376d42a7cc`. A subsequent fresh-environment check on **CPython 3.13.13, macOS 14.6, arm64** installed the application and report requirements, passed `pip check`, and passed all nine synthetic tests in [check_environment.py](../scripts/check_environment.py). No project analysis modules were imported and no real datasets were used.

The checks cover Parquet values/nulls/timezones, Excel, GeoPackage geometry and CRS, projection and nearest spatial join, geometry union, grouped apply, Spearman correlation, headless PNG rendering, and Word save/reopen. The Word check explicitly skips when python-docx is unavailable. Test artifacts and Matplotlib configuration/cache are temporary. These checks establish operation of the exercised package APIs on this platform, not correctness of scientific results or successful end-to-end execution.

### Dependency files and tested commands

- [requirements.txt](../requirements.txt): nine direct application dependencies, pinned to the initially selected versions; all installed without substitutions.
- [requirements-reports.txt](../requirements-reports.txt): application dependencies plus optional python-docx.
- [requirements-lock.txt](../requirements-lock.txt): the 24 resolved application/report packages tested on this platform, including transitive dependencies and excluding pip/setuptools/wheel. This is not a universal cross-platform or hash-verified lock.

Run from the repository root. The following commands represent the tested procedure with a newly allocated temporary path; they do not replace `.venv`. The interpreter path is specific to the tested macOS installation and its version must be checked before use.

```sh
set -e
python_bin=/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13
"$python_bin" -I -B --version  # tested: Python 3.13.13
check_dir=$(mktemp -d /private/tmp/transport-env-check-XXXXXXXX)
"$python_bin" -I -B -m venv "$check_dir/venv"
"$check_dir/venv/bin/python" -I -B -m pip --disable-pip-version-check --no-cache-dir install -r requirements-reports.txt > "$check_dir/install.log" 2>&1
"$check_dir/venv/bin/python" -I -B -m pip --disable-pip-version-check --no-cache-dir check > "$check_dir/pip-check.log" 2>&1
"$check_dir/venv/bin/python" -I -B scripts/check_environment.py > "$check_dir/smoke.log" 2>&1
```

To request the exact resolved package set on the tested platform, substitute `requirements-lock.txt` for `requirements-reports.txt` in the installation command. That separate installation has not been rerun; lock consistency was checked against the freshly tested environment without changing it:

```sh
"$check_dir/venv/bin/python" -I -B -m pip --disable-pip-version-check --no-cache-dir install --dry-run --no-index --report "$check_dir/lock-check.json" -r requirements-lock.txt > "$check_dir/lock-check.log" 2>&1
```

The dry-run report proposed no installations. This verifies consistency with installed packages, not availability for other platforms. The first sandboxed installation attempt failed DNS resolution; the network-enabled retry used normal package-source TLS verification and succeeded without changing pins. No package installation was performed in the original `.venv` or global environment.

### Remaining analysis blockers

An [isolated cleaned-data-to-usage run](validation/usage-reproduction.md) reproduced all 98 artifacts emitted by harmonization and Exercise 1 analytical scripts, with no material discrepancy against local references. Raw-to-cleaned processing was not rerun. Six legacy hourly artifacts were not emitted or validated; figures/reports and other exercises remain unverified. No supported Python/platform range beyond the environment above has been established.

Known blockers and limitations:

- The four Exercise 2 map/appendix scripts and root Stages 5–7 now derive project paths from their script locations. Isolated path-expression checks confirmed the same intended input/output locations from the repository root and an unrelated temporary working directory; no analyses were executed. Explicit absolute PT-proximity input overrides remain supported. The shell commands above still assume invocation from the repository root.
- [GTFS acquisition script](../src/data_loading/download_gtt_gtfs_archive.py) is empty. A historical feed matching the scooter observation period is not established by the local feed.
- Stage 4 → Stage 5 commuting costs are manually copied constants; their agreement has not been independently checked.
- There are no scientific pipeline regression tests; the new environment smoke checks use only synthetic fixtures. Several analysis scripts assert dataset-specific counts, and some create directories or perform work at module scope; importing them is not a safe substitute for static inspection.

A full reproduction still needs an agreed data distribution/provenance record, raw-to-cleaned validation, and controlled execution/reconciliation of the remaining analyses and figure/report workflows. The completed usage check does not establish those results.
